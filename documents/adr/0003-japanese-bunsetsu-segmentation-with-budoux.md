# 0003. 日本語の文節分割に BudouX を使い、言語は段落ごとに判定する

## Status
Accepted

## Context
RSVP で 1 回に表示する単位を、日本語は文節、英語は単語にする (`documents/PROJECT.md`)。分割はブラウザ内だけで行い (ADR 0001)、辞書・モデルもブラウザへ配信するため、その大きさが読み込み時間に効く (ADR 0001 の Consequences で、この判断を分割方式を決める issue に委ねた)。

2026-09-28 に比べた候補 (BudouX の大きさは npm tarball の実物、形態素解析の wasm の大きさは issue #2 の記載による):

| 候補 | ブラウザへ配る大きさ | 区切りの単位 | 評価 |
| --- | --- | --- | --- |
| BudouX (Google、Apache-2.0、npm 0.9.2) | 日本語モデル `module/data/models/ja.js` が 23.8KB (gzip 前)。ほかは約 4KB の parser だけ | 改行位置の候補として学習した句の区切りで、文節に近い | 採用 |
| `Intl.Segmenter` の単語分割 + 付属語を前の語へ結合する独自処理 | 0 (ブラウザ組み込み) | 単語。品詞を返さないため、助詞・助動詞を見分ける表を自前で持つ必要がある | 付属語の表の保守が要り、表に無い語で区切りが細かくなる |
| 形態素解析の wasm (kuromoji.js、Sudachi の WASM 版) | kuromoji.js の辞書が gzip で約 17.8MB、Sudachi の WASM 版は 50MB 超 | 形態素 (品詞付き) を文節にまとめる処理が別に要る | 初回の読み込みが重く、静的サイトに向かない |

BudouX 0.9.2 の parser に青空文庫の夏目漱石「吾輩は猫である」の冒頭を通すと、「吾輩は / 猫である。 / 名前は / まだ / 無い。」のように文節に近い区切りが出る (区切り全体は `src/lib/readingUnits.test.ts`)。平均は 1 文節約 4.6 文字で、競合への批判「日本語の区切りが細かすぎる」(IdeaMemo #341 の評価レポート) に当たらない。ラテン文字の連続は区切らないため、日本語の文の中の英単語は 1 つの塊で返る。

## Decision
- 日本語の文節分割に BudouX の `Parser` と日本語モデル (`jaModel`) を使う。HTML を扱う `HTMLProcessingParser` は使わない
- 日本語の段落は、文末記号 (。．！？!?) とその後の閉じ括弧・閉じ引用符までで文に分けてから、文ごとに BudouX で分ける。BudouX の塊の中の空白でさらに分け (日本語の文の中の英単語を 1 語ずつにするため)、空白だけの部分は単位にしない。サロゲートペアの間の区切りは捨てる
- 英語は空白で単語に分け、句読点は前の単語に付けたままにする。単語の末尾が . ! ? (後に閉じ引用符・閉じ括弧が続いてもよい) なら文末とし、Mr. / Dr. / e.g. などの略語は文末にしない
- 改行 (CR・LF・U+2028・U+2029) で区切った各行を段落とする (青空文庫の txt は 1 行が 1 段落のため)。段落ごとに、仮名・漢字を含めば日本語、含まなければ英語と判定する。表示時間は単位ごとに、仮名・漢字を含む単位は日本語の速度 (1 分あたりの文字数)、含まない単位は英語の速度 (1 分あたりの単語数) で計算する
- 間は、読点類 (、，,;；:：)・文末・段落の終わりだけから決め、単位の中身 (固有名詞かどうか等) では表示時間を変えない (ADR 0002)

## Consequences
- 本文を扱う依存に `budoux` が加わる。parser・日本語モデル・`index`・`html_processor`・`dom` / `dom-browser` のソースに `fetch` / `XMLHttpRequest` / `sendBeacon` / `WebSocket` / 動的 `import()` が無いことを 2026-09-28 に 0.9.2 の npm tarball で確認した。npm の `dependencies` の `commander`・`google-artifactregistry-auth`・`linkedom` は CLI と Node.js での HTML 処理のためのもので、ブラウザの経路 (`browser` フィールドで `dom-browser.js` に置き換わる) では使わない
- ブラウザへ配る大きさは、`budoux` の `sideEffects` の指定で使わないモデル (中国語・タイ語) と HTML 処理が tree-shaking で落ちる前提で、日本語モデルと parser の約 28KB (gzip 前) を見込む。この PR の時点ではページから読み込んでいないため、実際の bundle の大きさはリーダー画面の issue で測る
- BudouX は改行位置のためのモデルで、品詞を返さない。助詞だけの短い単位 (「GitHub Pages で」の「で」) が出ることがある。区切りを変える時は、BudouX の出力の後処理を足すか、この ADR を置き換える
- 「」の中の文末 (「行こう。」と言った。) では「「行こう。」」と「と言った。」の 2 文に切れる。英文の訳は英語の段落にしか使わないため、日本語の文の区切りの粗さは訳の機能に影響しない
