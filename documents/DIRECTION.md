# 方向性: sokudoku

## 仮説

長い文章 (日本語の小説・技術書、英文の記事・本) を内容を理解したまま速く読みたい bannzai 自身が、デスクトップのブラウザで、手元のテキスト・DRM の無いファイルを 1 文節 (単語) ずつ同じ位置に表示する RSVP で読み、英文は分からない文だけ端末内の翻訳で日本語訳を出し入れすることで、読む速度を上げる。

- [ ] アクセス解析 (Cloudflare Web Analytics の beacon)

## デザインの方向

agent が作ったモック (`documents/design/mock-2026-10-01/index.html`。方針は https://github.com/bannzai/sokudoku/issues/9#issuecomment-5917877306 ) の見た目と体験に合わせる。値は `src/app/globals.css` のデザイントークンを正とし、画面を足す時も同じトークンを使う。

- 配色: 長く読んでも眩しくないよう、ライトは白の地と青みの墨色、ダークは青みのある黒に近い地と真っ白にしない文字色にする。アクセントは藍色 1 色で、停止中の全文の現在位置は薄い藍でハイライトする
- 書体: 文節と全文は明朝 (日本語は BIZ UDPMincho、英語は Literata)、画面の操作と説明は BIZ UDPGothic。フォントはビルド時に取得して同じオリジンから配信する
- レイアウト: 再生中は画面の上寄りの固定の位置に文節 1 つと上下の細い縦線だけを出し、操作は下にまとめて薄く出す。ボタンには対応するキーを併記する
- ADR 0002 の制約 (中央揃え・単色・単一の太さ、再生中に全文を出さない) はデザインより優先する
